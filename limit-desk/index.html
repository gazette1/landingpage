What one parameter change does

Pick a parameter. Every column reruns the whole desk, the applications and the book, with only that parameter changed.

One result to read with care: a tighter cash rule can leave more book limits in force, not fewer. When a recomputed limit falls below the card balance, the written policy sends the account to referral, and a referred account keeps its current limit until a person decides. The table shows the rule as written, which is a reason to review the rule.

How this page is made

Every sentence is deterministic text. The memos and rationales are assembled from rule ids and computed figures by fixed templates. No model is called, here or at build time. The same inputs give the same words.

Every figure comes from one engine. A single JavaScript file computes every measure, flag, decision, limit, monitoring action and table on this page from the synthetic data embedded in it.

A second implementation checks it. A Python program written from the policy text, with exact rational arithmetic, computes the same figures. The checks in section 7 compare the two to the cent.

A publish gate and planted mistakes. The page is published only if every check passes and the page itself passes a lint for banned characters, external resources and labeling. A separate script plants mistakes in the rules and the data, one at a time, and confirms the gate stops each one.

What it does not show. The companies, accounts, policy and outcomes are invented. Real underwriting would add documents the bank feed does not carry: financial statements, the cap table, the investor's commitment, and a conversation with the founder about what the numbers do not show.
