How it works

      

        
The workflow. A billing analyst runs the quarter. Code computes what each invoice line should have been from signed terms only, compares it with what billing sent, and tests each gap against known causes: an uplift that never reached billing, overage not charged at the contract rate, a change billed without a signed order form, a signed change billing never applied. Anything it cannot explain goes to a person as unexplained. An AI model drafts a note for each finding, a gate checks the note, and a reviewer decides each one before the batch goes to billing.

        
What the model is allowed to do. Write. It never computes a number and never decides. The notes were drafted once by  and are re-checked by the gate on every load. A note may not promise a refund or credit, claim the customer agreed, accuse anyone, or tell billing to contact the customer.

        
Why the evals look like this. A reconciler fails in two directions: it misses money, or it raises alarms on accounts billed correctly, which costs reviewer trust. So the answer key has nine planted errors and six decoys (accounts that look unusual but are right), every figure is recomputed by a separate Python implementation, the gate has its own tests with known answers, and three simulated regressions prove the checks catch plausible bugs: an off-by-one on the uplift month, overage netted across the quarter, and trusting the CRM over the contracts folder.

        
How it was built. With Claude Code, in one session: the engine, the Python cross-check, the note generator, and check.mjs, which runs these checks in Node and exits non-zero on any failure. The build script will not write the published copy unless that gate passes, so the page you are reading passed it.
