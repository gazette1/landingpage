A model drafted the sentences at build time and a numbers gate checks them. A person classifies, signs and locks.

What the drafting model is told

Rules this page applies, in order

  • Close state: an open month defers the row; a pending journal holds it.
  • Snapshot: a journal counts only if posted on or before the snapshot's close day.
  • Mapping: a mapped cost center is summed into its target row and retired as its own row.
  • Plan basis: the filed reforecast per cost center, or its budget where none is filed. Never zero.
  • Variance and flag: rounded percent above T and amount at least F; plan of $0 with spend of at least F is unplanned spend.
  • Totals: deferred rows are excluded and named.

2Variance results

Variance is adjusted actual minus plan; positive is overspend. Percent is rounded half away from zero to one decimal, and the flag rule uses the rounded figure. FTE is the September value. Select any figure to see its formula, the source fields with values, and the version tags.

3Commentary and numbers gate

Drafts are cached under a hash of the row's facts, so a rerun reuses the same text when the facts did not change and a new draft is needed only when they did. Every dollar amount, percent, and FTE count in a draft must match a figure in that row's facts, the company totals, or the policy. A draft must name the cost center and its exact variance, and may not use an em dash, an exclamation point, or the words one-time, continuing, or timing. The gate cannot catch an invented cause stated without numbers; the reviewer covers that.

4Compare runs

Run A is a locked version; run B is the current controls. Inputs are changed one at a time in a fixed order: close state, snapshot, mapping, plan basis, policy, journal decisions. Each step's change is attributed to that step, and the steps sum exactly to B minus A. The order matters only when two changes touch the same row.

6Classify, sign and lock

The model never classifies a variance. The FP&A lead classifies each flagged one, signs, and locks the version. Locking needs the release gate allowed, no deferred or held rows, every flagged row classified with a passing draft, and a name.

    Lock records
    Q3-v1 was written once by a build script that refuses to overwrite a version. A lock made on this page is a session record: it can be exported as Markdown and used as run A, and nothing is sent or stored. The name is typed, not verified.

    7Measurement and limits

    What the model cost and saw, what a rerun costs, what is mocked, and what this does not establish.

    What the model is allowed to do. Write sentences. It drafts one paragraph per cost center state at build time from a facts object the engine computed. It never computes, classifies, decides the flag, or runs in the browser. Caching by facts hash makes the released text repeatable on a rerun; it does not make the model deterministic. New text appears only when facts change, and it must pass the numbers gate and a person.

    Why the checks look like this. The first test of a finance workflow after go-live is a rerun after the books move. R5 and R6 are realistic rerun mistakes: a rerun that reads the latest snapshot instead of the version's own, and a missing reforecast read as a plan of zero. Each must fail a named check, or the suite reports itself as too weak. G&A at 4.9 percent and Customer Success at $9,000 are decoys that sit just inside the policy.

    Implemented. Snapshot, mapping and plan-basis rules, the variance engine, deferral and hold, lineage for every figure, stepwise run comparison, replay to a SHA-256 lock hash, the numbers gate, evals E01 to E17, six simulated regressions, the Python cross-check, rule drafts, build-time AI drafts cached by facts hash, lock rules and the pack export. Mocked. The governed data source (a JSON file stands in for what a customer would expose to the workflow), snapshots (a posted-day filter, not a ledger snapshot service), permissions (none), lock storage (a file written once by a script; page locks are session-only) and sign-off identity (a typed name).

    What this does not establish. Behavior on a real ledger or inside any vendor's product, model quality on real data, that ten scenarios are enough, or time saved. The same person wrote the data and the answer key, so the results show the logic, attribution, refusals and checks on a known case, not accuracy in the field.
