Is the Q3 variance agent ready to go live?

A go-live pack for one Custom Agent of the kind Pigment documents: an FP&A analyst that explains opex variances against plan and flags those over 5 percent. Code computes every figure. An AI model drafted the commentary at build time and a numbers gate checks it. A person classifies each variance and signs. The evals decide whether the configuration can ship, and the close decides whether the agent may speak.

3Commentary and numbers gate

Every dollar amount, percent, and FTE count in a draft must match a figure in that row's facts, the company totals, or the policy, within half of the last digit shown. A draft must name the cost center and its exact variance, and may not use an em dash, an exclamation point, or the words one-time, continuing, or timing. Edit a draft and the gate runs again. The gate cannot catch an invented cause stated without numbers; the reviewer covers that.

4Eval and release gate

Fourteen close scenarios checked against a hand-built answer key, an independent Python implementation, and seven gate tests. The same checks run in Node before every publish. Pick a simulated regression: it changes the engine for the whole page, and the evals have to block it.

5Sign-off and go-live pack

The agent never classifies a variance. The FP&A lead classifies each flagged one and signs the Functionality / Use Case Sign-Off (Stencil's term). Go-live needs the release gate allowed, no deferred or held rows, every flagged row classified with a passing draft, and a name.

    The pack downloads as Markdown from this page; nothing is sent anywhere. The name is typed, not verified, and is not saved.

    How it works

    The decision. Is this variance agent ready to go live for the Q3 close, and if not, what blocks it and who has to decide. The deployer owns the configuration and its acceptance tests; the Controller owns journal decisions; the FP&A lead owns classification and sign-off.

    What the model is allowed to do. Write. drafted one note per cost center at build time from figures the engine computed, with the Spec's Instructions and Knowledge as its system prompt. It never computes, never classifies, and never runs in the browser. A draft is shown only when its facts match the current figures exactly; otherwise the page shows the rule-based draft and says so.

    Why the evals look like this. A variance agent fails in quiet ways on a messy close. The four simulated regressions are realistic mistakes: headcount summed across months, favorable variances ignored, an unloaded month counted as zero, and a pending reclass ignored. Each one must fail a named scenario, or the suite reports itself as too weak. G&A at 4.9 percent and Customer Success at $9,000 are decoys that sit just inside the policy.

    Implemented. The variance engine, deferral and hold, the numbers gate, 14 eval scenarios, 4 regressions, 7 gate tests, the Python cross-check, rule drafts, build-time AI drafts, sign-off logic, and the pack export. Mocked or absent. Pigment itself, the Custom Agent runtime, Skills, permission inheritance, data connectors, and identity and persistence of sign-offs.
